3. Mini-Project 1: Priority Traffic Intersection Controller with Pedestrian Override 🚦

🎯 Objective

In urban traffic safety systems, traffic lights sequence sequentially through Green, Yellow, and Red phases. In this mini-project, you will program the STM32 Nucleo-C031C6 to control a 3-LED traffic junction and safely handle pedestrian push-to-cross requests.

🛠️ Hardware Setup (Wokwi)

The circuit connects the following to an STM32 Nucleo-C031C6 board: * 3x LEDs (Red, Yellow, Green): With 220Ω current-limiting resistors. * 1x Pushbutton: Pedestrian call button on D2 (PA10).

Pin Wiring Table

Component Pin / Terminal STM32 / Board Pin Electrical Function
Red LED Anode (via 220Ω resistor) D13 (PA5) Stop Phase Indicator
Yellow LED Anode (via 220Ω resistor) D12 (PA6) Caution / Transition Phase Indicator
Green LED Anode (via 220Ω resistor) D11 (PA7) Go Phase Indicator
All LEDs Cathodes (\(-\)) Common GND Ground Reference
Pedestrian Button Terminal 1.L / 2.L D2 (PA10) / GND Pedestrian Call (INPUT_PULLUP)

📝 Problem Statement & Logic Flow

  1. Default Traffic Cycle:
    • Phase 1 (Go): Green LED is ON for 4.0 seconds. Red and Yellow are OFF.
    • Phase 2 (Caution): Green turns OFF; Yellow LED is ON for 1.5 seconds.
    • Phase 3 (Stop): Yellow turns OFF; Red LED is ON for 4.0 seconds (allowing cross traffic).
  2. Pedestrian Priority Override:
    • When a pedestrian presses the button on D2 while the light is Green, do not jump instantly to Red (which causes vehicular collisions!). Instead, immediately abort the remaining Green duration and transition to the 1.5-second Yellow caution phase, followed by Red.
  3. Serial Telemetry:
    • Transmit live state updates over UART at 115200 baud.
[STATE] GREEN - Traffic Moving
[PEDESTRIAN] Button Pressed! Initiating Stop Sequence...
[STATE] YELLOW - Prepare to Stop
[STATE] RED - Pedestrians Crossing

// ============================================================================
// Mini-Project 1: Multi-LED Traffic Signal Controller (Nucleo-C031C6)
// ============================================================================

#define LED_RED    13 // PA5 (User LED)
#define LED_YELLOW 12 // PA6
#define LED_GREEN  11 // PA7
#define BUTTON_PIN 2  // Pedestrian Call Button

void setup() {
  Serial.begin(115200);
  pinMode(LED_RED, OUTPUT);
  pinMode(LED_YELLOW, OUTPUT);
  pinMode(LED_GREEN, OUTPUT);
  pinMode(BUTTON_PIN, INPUT_PULLUP);

  Serial.println("--- Traffic Signal Controller Initialized ---");
}

void loop() {
  // Phase 1: Green ON (Go Phase - 4000 ms with responsive pedestrian check)
  digitalWrite(LED_RED, LOW);
  digitalWrite(LED_YELLOW, LOW);
  digitalWrite(LED_GREEN, HIGH);
  Serial.println("[STATE] GREEN - Traffic Moving");

  for (int i = 0; i < 80; i++) {
    if (digitalRead(BUTTON_PIN) == LOW) {
      Serial.println("[PEDESTRIAN] Button Pressed! Initiating Stop Sequence...");
      break; // Abort remaining green phase
    }
    delay(50);
  }

  // Phase 2: Yellow ON (Caution Phase - 1500 ms)
  digitalWrite(LED_GREEN, LOW);
  digitalWrite(LED_YELLOW, HIGH);
  Serial.println("[STATE] YELLOW - Prepare to Stop");
  delay(1500);

  // Phase 3: Red ON (Stop Phase - 4000 ms)
  digitalWrite(LED_YELLOW, LOW);
  digitalWrite(LED_RED, HIGH);
  Serial.println("[STATE] RED - Pedestrians Crossing");
  delay(4000);
}
// ============================================================================
// Mini-Project 1: STM32 HAL Multi-LED Sequencer
// ============================================================================
#include "stm32c0xx_hal.h"

#define LED_RED_PIN     GPIO_PIN_5
#define LED_YELLOW_PIN  GPIO_PIN_6
#define LED_GREEN_PIN   GPIO_PIN_7
#define LED_PORT        GPIOA

void traffic_cycle_step(void) {
    // 1. Red ON
    HAL_GPIO_WritePin(LED_PORT, LED_RED_PIN, GPIO_PIN_SET);
    HAL_GPIO_WritePin(LED_PORT, LED_YELLOW_PIN | LED_GREEN_PIN, GPIO_PIN_RESET);
    HAL_Delay(4000);

    // 2. Yellow ON
    HAL_GPIO_WritePin(LED_PORT, LED_YELLOW_PIN, GPIO_PIN_SET);
    HAL_GPIO_WritePin(LED_PORT, LED_RED_PIN | LED_GREEN_PIN, GPIO_PIN_RESET);
    HAL_Delay(1500);

    // 3. Green ON
    HAL_GPIO_WritePin(LED_PORT, LED_GREEN_PIN, GPIO_PIN_SET);
    HAL_GPIO_WritePin(LED_PORT, LED_RED_PIN | LED_YELLOW_PIN, GPIO_PIN_RESET);
    HAL_Delay(4000);
}

4. Mini-Project 2: Hardware Timer & 50 Hz PWM Servo Actuator ⚙️🤖

🎯 Objective

In robotic actuators and precise timing systems, software delays jitter uncontrollably when CPU load fluctuates. In this project, you will configure Hardware Timer 1 to output a 50 Hz Fast PWM waveform (\(20\text{ ms}\) period) to position an RC servo motor smoothly across \(0^\circ\), \(90^\circ\), and \(180^\circ\).

🛠️ Hardware Setup (Wokwi)

The circuit connects the following components: * 1x Hobby Servo Motor (wokwi-servo): Signal connected to Pin 9 (Timer 1 PWM). * Onboard LED: On Pin 13 / PB5.

Pin Wiring Table

Component Pin / Terminal Board Pin Electrical Function
Servo Motor Signal (Orange) Pin 9 (PB1 / OC1A) Hardware Timer 1 Fast PWM Output
Servo Motor VCC (Red) 5V Motor Power Supply
Servo Motor GND (Brown/Black) GND Ground Reference

📝 Problem Statement & Logic Flow

  1. PWM Frequency & Period: Generate an exact \(50\text{ Hz}\) waveform (\(20\text{ ms}\) total period).
  2. Angle Mapping (Pulse Widths):
    • \(0^\circ\) Angle: \(1.0\text{ ms}\) high pulse (hold 1 sec).
    • \(90^\circ\) Angle (Center): \(1.5\text{ ms}\) high pulse (hold 1 sec).
    • \(180^\circ\) Angle: \(2.0\text{ ms}\) high pulse (hold 1 sec).
  3. Register Calculations (16 MHz Clock, Prescaler = 8):
    • 1 timer tick \(= \frac{8}{16,000,000} = 0.5\,\mu\text{s}\).
    • TOP (20 ms period): \(\text{ICR1} = 39,999\).
    • \(0^\circ\) (1.0 ms pulse): \(\text{OCR1A} = 2,000\).
    • \(90^\circ\) (1.5 ms pulse): \(\text{OCR1A} = 3,000\).
    • \(180^\circ\) (2.0 ms pulse): \(\text{OCR1A} = 4,000\).

// ============================================================================
// Mini-Project 2: Servo Control using High-Level Framework (Servo.h)
// ============================================================================
#include <Servo.h>

Servo myServo;

void setup() {
  Serial.begin(115200);
  myServo.attach(9); // Digital Pin 9 (PB1 / OC1A)
  Serial.println("--- Servo Hardware PWM Sweeper Started ---");
}

void loop() {
  Serial.println("[SERVO] Angle: 0 deg (Pulse: 1.0 ms)");
  myServo.write(0);   // Sweep to 0 degrees
  delay(1000);

  Serial.println("[SERVO] Angle: 90 deg (Pulse: 1.5 ms)");
  myServo.write(90);  // Center at 90 degrees
  delay(1000);

  Serial.println("[SERVO] Angle: 180 deg (Pulse: 2.0 ms)");
  myServo.write(180); // Sweep to 180 degrees
  delay(1000);
}
// ============================================================================
// Mini-Project 2: Register-Level Fast PWM (Timer 1)
// ============================================================================
#include <avr/io.h>
#include <util/delay.h>

void servo_timer_init(void) {
    DDRB |= (1 << PB1); // Pin 9 as Output

    // Configure Timer 1 for 50 Hz Fast PWM (ICR1 as TOP, Prescaler = 8)
    TCCR1A = (1 << COM1A1) | (1 << WGM11);
    TCCR1B = (1 << WGM13)  | (1 << WGM12) | (1 << CS11); // Prescaler 8
    ICR1   = 39999;                                       // 20 ms Period (50 Hz)
    OCR1A  = 3000;                                        // Neutral 90 deg (1.5 ms)
}

void set_servo_angle(uint8_t angle) {
    if (angle > 180) angle = 180;
    // Map 0-180 deg to 2000-4000 ticks (1.0 ms to 2.0 ms)
    OCR1A = 2000 + ((uint32_t)angle * 2000) / 180;
}

7. Concept Check Practice Questions

Question 1: Timer CTC Mode Compare Match Calculation

NoteClick to View Question & Options

An ATmega328P runs at \(f_{CPU} = 16\text{ MHz}\). You configure Timer 1 in CTC mode with a Prescaler of \(64\). What value must be loaded into the OCR1A register to generate a periodic interrupt frequency of exactly \(500\text{ Hz}\)?

Options:
- A) \(250\)
- B) \(499\)
- C) \(500\)
- D) \(3124\)

Tip✅ Correct Answer: B

Explanation:
The formula for CTC mode is:
\[\text{OCR1A} = \left( \frac{f_{CPU}}{\text{Prescaler} \times f_{\text{target}}} \right) - 1 = \left( \frac{16,000,000}{64 \times 500} \right) - 1 = \left( \frac{16,000,000}{32,000} \right) - 1 = 500 - 1 = \mathbf{499}\].

Question 2: Servo Motor PWM Signal Timing

NoteClick to View Question & Options

What is the standard signal frequency and pulse width required to command a standard hobby servo motor to its neutral center (\(90^\circ\)) position?

Options:
- A) \(1000\text{ Hz}\) frequency with \(50\%\) duty cycle
- B) \(50\text{ Hz}\) frequency (\(20\text{ ms}\) period) with a \(1.5\text{ ms}\) active-high pulse
- C) \(10\text{ kHz}\) frequency with a \(10.0\text{ ms}\) pulse
- D) Constant DC voltage of \(2.5\text{ V}\)

Tip✅ Correct Answer: B

Explanation:
Standard hobby RC servos require a \(50\text{ Hz}\) repetition rate (\(20\text{ ms}\) frame). The pulse width controls position: \(1.0\text{ ms}\) is \(0^\circ\), \(1.5\text{ ms}\) is \(90^\circ\) (center), and \(2.0\text{ ms}\) is \(180^\circ\).
