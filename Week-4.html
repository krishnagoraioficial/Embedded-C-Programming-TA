Week 4: Advanced Peripheral Interfacing (Timers & ADC)

1. Combinational vs. Sequential Logic Elements

In digital system design and microcontroller architecture, logic circuits are classified into two categories:

  COMBINATIONAL CIRCUIT                           SEQUENTIAL CIRCUIT
+-------------------------+                 +-------------------------------+
| Output = f(Inputs)      |                 | Output = f(Inputs, State)     |
| - No memory / no clock  |                 | - Contains memory (Flip-Flops)|
| - Immediate response    |                 | - Synchronized by Clock Edge  |
| Ex: Adders, MUX, ALU    |                 | Ex: Counters, Timers, ShiftReg|
+-------------------------+                 +-------------------------------+

Why Edge-Triggered Flip-Flops are Standard

Microcontroller registers and timers use edge-triggered D flip-flops rather than level-sensitive latches because they sample inputs only at the instantaneous transition of the clock signal (e.g., rising edge from 0 to 1). This eliminates race conditions and ensures clean, deterministic synchronous data movement.

2. Microcontroller Hardware Timers & PWM

Hardware timers are autonomous peripheral blocks that count clock pulses independently of the CPU, enabling precision delays, event scheduling, and waveform generation without consuming processor cycles.

 +---------------+     +--------------------+     +-----------------------+
 | Internal Clock| ==> | Prescaler Register | ==> |   Counter Register    |
 |  (e.g., 48MHz)|     |      (PSC)         |     |        (CNT)          |
 +---------------+     +--------------------+     +-----------------------+
                                                              |
                                                              v  (When CNT == ARR)
                                                  +-----------------------+
                                                  |  Auto-Reload Register |
                                                  |        (ARR)          |
                                                  +-----------------------+
                                                              |
                                                              v
                                                    [ Timer Interrupt / ]
                                                    [  PWM Event Fired  ]

Key Timer Formulas

  1. Timer Overflow Frequency (\(f_{\text{timer}}\)): \[f_{\text{timer}} = \frac{f_{\text{CLK}}}{(\text{PSC} + 1) \times (\text{ARR} + 1)}\]

  2. Timer Overflow Period (\(T_{\text{overflow}}\)): \[T_{\text{overflow}} = \frac{1}{f_{\text{timer}}} = \frac{(\text{PSC} + 1) \times (\text{ARR} + 1)}{f_{\text{CLK}}}\]

  3. Pulse-Width Modulation (PWM) Duty Cycle: \[\text{Duty Cycle (\%)} = \frac{\text{CCR}}{\text{ARR}} \times 100\%\] (Where \(\text{CCR}\) is the Capture/Compare Register value).

Calculation Example

If an STM32 timer operates with a 48 MHz clock, \(\text{PSC} = 47\), and \(\text{ARR} = 999\): \[f_{\text{timer}} = \frac{48,000,000}{(47 + 1) \times (999 + 1)} = \frac{48,000,000}{48 \times 1000} = \mathbf{1,000\text{ Hz}}\ (1\text{ kHz})\] The timer will overflow exactly once every 1 millisecond.

3. Analog-to-Digital Conversion (ADC)

Microcontrollers operate on binary signals (0 or 1), but physical phenomena (temperature, pressure, audio, battery voltage) produce continuous analog voltages. The Analog-to-Digital Converter (ADC) bridges this gap through sampling and quantization.

 Continuous Analog Signal             Sampling                   Quantization
   (Smooth Voltage Wave)     ===>  (Discrete Time)   ===>  (Digital Binary Code)
           ~                           | | | |                  0x03FF (10-bit)

Core ADC Principles

  1. Sampling Rate (Nyquist Theorem): To reconstruct an analog signal accurately without aliasing, the sampling frequency (\(f_s\)) must be at least twice the maximum frequency component (\(f_{\text{max}}\)) present in the signal: \[f_s \ge 2 \times f_{\text{max}}\]

  2. Quantization Levels (\(N\)-bit ADC): An \(N\)-bit ADC maps the reference voltage range into \(2^N\) distinct digital levels:

    • 8-bit ADC: \(2^8 = \mathbf{256}\) levels
    • 10-bit ADC: \(2^{10} = \mathbf{1024}\) levels (e.g., 0 to 1023)
    • 12-bit ADC (Standard STM32): \(2^{12} = \mathbf{4096}\) levels (e.g., 0 to 4095)

  3. Voltage Step Resolution (\(V_{\text{step}}\)): \[V_{\text{step}} = \frac{V_{\text{REF}}}{2^N}\] Example: For a 12-bit ADC with \(V_{\text{REF}} = 3.3\text{V}\): \[V_{\text{step}} = \frac{3.3\text{V}}{4096} \approx \mathbf{0.805\text{ mV per LSB}}\]

4. Microcontroller Power Management & Low-Power Modes

In battery-powered IoT devices and wearable electronics, maximizing battery runtime requires aggressive power management. Microcontrollers provide multiple power modes:

 Mode               CPU State       Peripherals         SRAM Content       Wakeup Latency
-----------------------------------------------------------------------------------------
 Run Mode           Active          Active              Retained           0 ns (Instant)
 Sleep Mode         Halted          Active (Timers/ADC) Retained           Few Clock Cycles
 Stop Mode          Halted          Clocks Disabled     Retained           Few Microseconds
 Standby Mode       Powered Down    Powered Down        Lost (Except RTC)  Full Reset Startup

Power Reduction Strategies in Firmware

  • Clock Prescaling: Reduce the main clock speed when high processing throughput is not required (\(P \propto f_{\text{CLK}} \cdot V^2\)).
  • Peripheral Clock Gating: Keep peripheral clocks turned off in RCC until immediately needed.
  • Interrupt-Driven Sleep: Execute tasks in response to interrupts, then immediately put the CPU to sleep with the __WFI() (Wait For Interrupt) instruction.

5. Mini-Project 1: Smart LED Dimmer (ADC to PWM Mapping) 🎛️💡

🎯 Objective

In this project, you connect two foundational Week 4 concepts: reading a continuously variable analog sensor (ADC) and outputting a continuous control signal (Pulse Width Modulation - PWM). You will build an embedded system that samples a potentiometer’s voltage and maps that value to adjust the exact duty cycle of a PWM signal, directly regulating the physical brightness of an LED.

🛠️ Hardware Setup (Wokwi)

The circuit connects the following components to an STM32 Nucleo-C031C6 board: * 1x Potentiometer: To simulate an analog voltage input. * 1x LED (Blue): To visualize the PWM duty cycle. * 1x 220Ω Resistor: Current-limiting resistor to protect the LED.

Potentiometer SIG (Signal) A0 Analog Input (PA0 / ADC Channel 0)
LED Anode (via 220Ω Resistor) D3 PWM Output (PB0 / Timer 3 Channel 3)

📝 Problem Statement & Logic Flow

  1. Initialization (setup):
    • Start UART Serial communication at 115200 baud rate.
    • Configure potentiometer pin (A0) as INPUT.
    • Configure LED pin (D3) as OUTPUT.
    • Configure ADC resolution to 10-bit (0 to 1023) using analogReadResolution(10);.
  2. Continuous Loop (loop):
    • Read Analog Value: Sample raw digital data from the potentiometer with analogRead(A0).
    • Map to PWM Range: The 10-bit ADC provides values from 0 to 1023. Standard PWM uses an 8-bit resolution (0 to 255). Use map() to translate the reading.
    • Control Brightness: Output the mapped PWM duty cycle to the LED pin using analogWrite().
    • Print to Terminal: Transmit the telemetry data over UART for monitoring.

// ============================================================================
// Mini-Project 1: The Smart Dimmer Challenge (ADC to PWM)
// ============================================================================

// We connect the potentiometer (knob) to this analog pin
#define knobPin A0

// We connect the LED to this pin because it has PWM (dimming) support
#define ledPin 3 

void setup() {
  // Start the serial monitor so we can see the values on our screen
  Serial.begin(115200);
  
  // Tell the board how we are using these pins
  pinMode(knobPin, INPUT);
  pinMode(ledPin, OUTPUT);
  
  // Set the ADC to 10-bit mode, which gives us readings from 0 to 1023
  analogReadResolution(10); 
  
  Serial.println("--- Smart Dimmer is Ready ---");
}

void loop() {
  // Step 1: Read the current position of the knob
  // Since it is 10-bit, this will be a number between 0 and 1023
  int knobReading = analogRead(knobPin);
  
  // Step 2: Convert the knob reading to an LED brightness level
  // The knob goes from 0-1023, but the LED PWM only accepts 0-255
  // The map() function shrinks our big number range into the smaller range
  int ledBrightness = map(knobReading, 0, 1023, 0, 255);
  
  // Step 3: Send that calculated brightness level to the physical LED
  analogWrite(ledPin, ledBrightness);
  
  // Step 4: Print the numbers to the screen so we can check our math
  Serial.print("Knob Reading: ");
  Serial.print(knobReading);
  Serial.print(" | LED Brightness: ");
  Serial.println(ledBrightness);
  
  // Wait a tiny bit before reading again so the text doesn't scroll too fast
  delay(100); 
}
// ============================================================================
// Mini-Project 1: Smart Dimmer (Bare-Metal STM32 Embedded C)
// Hardware: STM32 Nucleo-C031C6
// Pin Mapping: Knob on PA0 (ADC1_IN0), LED on PB0 (TIM3_CH3 PWM)
// ============================================================================

#include <stdint.h>

// 1. STM32 Peripheral Register Base Addresses
#define RCC_BASE            (0x40021000UL)
#define RCC_IOPENR          (*(volatile uint32_t *)(RCC_BASE + 0x34UL))
#define RCC_APBENR1         (*(volatile uint32_t *)(RCC_BASE + 0x3CUL))
#define RCC_APBENR2         (*(volatile uint32_t *)(RCC_BASE + 0x40UL))

#define GPIOA_BASE          (0x50000000UL)
#define GPIOA_MODER         (*(volatile uint32_t *)(GPIOA_BASE + 0x00UL))

#define GPIOB_BASE          (0x50000400UL)
#define GPIOB_MODER         (*(volatile uint32_t *)(GPIOB_BASE + 0x00UL))
#define GPIOB_AFRL          (*(volatile uint32_t *)(GPIOB_BASE + 0x20UL))

// Timer 3 (PWM Generation on PB0 / Arduino D3)
#define TIM3_BASE           (0x40000400UL)
#define TIM3_CR1            (*(volatile uint32_t *)(TIM3_BASE + 0x00UL))
#define TIM3_CCMR1          (*(volatile uint32_t *)(TIM3_BASE + 0x18UL))
#define TIM3_CCER           (*(volatile uint32_t *)(TIM3_BASE + 0x20UL))
#define TIM3_PSC            (*(volatile uint32_t *)(TIM3_BASE + 0x28UL))
#define TIM3_ARR            (*(volatile uint32_t *)(TIM3_BASE + 0x2CUL))
#define TIM3_CCR3           (*(volatile uint32_t *)(TIM3_BASE + 0x3CUL))

// ADC1 (Analog-to-Digital Converter on PA0 / Arduino A0)
#define ADC1_BASE           (0x40012400UL)
#define ADC1_ISR            (*(volatile uint32_t *)(ADC1_BASE + 0x00UL))
#define ADC1_CR             (*(volatile uint32_t *)(ADC1_BASE + 0x08UL))
#define ADC1_CFGR1          (*(volatile uint32_t *)(ADC1_BASE + 0x0CUL))
#define ADC1_CHSELR         (*(volatile uint32_t *)(ADC1_BASE + 0x28UL))
#define ADC1_DR             (*(volatile uint32_t *)(ADC1_BASE + 0x40UL))

/**
 * @brief Initialize ADC1 for 10-bit single-channel conversion on PA0
 */
void adc_init(void) {
    // 1. Enable GPIOA and ADC1 peripheral clocks
    RCC_IOPENR  |= (1U << 0);  // Bit 0: GPIOA clock enable
    RCC_APBENR2 |= (1U << 20); // Bit 20: ADC clock enable

    // 2. Configure PA0 (A0) in Analog Mode ('11' in MODER)
    GPIOA_MODER |= (3UL << (0 * 2));

    // 3. ADC Self-Calibration
    ADC1_CR |= (1U << 31); // Start calibration (ADCAL)
    while (ADC1_CR & (1U << 31)); // Wait until calibration completes

    // 4. Enable ADC
    ADC1_ISR |= (1U << 0); // Clear ADRDY flag
    ADC1_CR  |= (1U << 0); // Assert ADEN
    while (!(ADC1_ISR & (1U << 0))); // Wait until ADC is ready

    // 5. Configure 10-bit resolution ('01' in CFGR1 RES[1:0] bits)
    ADC1_CFGR1 &= ~(3UL << 3);
    ADC1_CFGR1 |=  (1UL << 3); // 10-bit resolution (0 to 1023)

    // 6. Select ADC Channel 0 (connected to PA0)
    ADC1_CHSELR = (1UL << 0);
}

/**
 * @brief Initialize TIM3 Channel 3 to produce 1 kHz PWM on PB0 (D3)
 */
void pwm_timer_init(void) {
    // 1. Enable GPIOB and TIM3 peripheral clocks
    RCC_IOPENR  |= (1U << 1);  // Bit 1: GPIOB clock enable
    RCC_APBENR1 |= (1U << 1);  // Bit 1: TIM3 clock enable

    // 2. Configure PB0 (D3) as Alternate Function ('10' in MODER)
    GPIOB_MODER &= ~(3UL << (0 * 2));
    GPIOB_MODER |=  (2UL << (0 * 2));
    GPIOB_AFRL  |=  (1UL << (0 * 4)); // AF1 = TIM3_CH3

    // 3. Configure Timer Prescaler and Auto-Reload for 1 kHz PWM
    TIM3_PSC = 47;   // 48 MHz / (47 + 1) = 1 MHz timer tick frequency
    TIM3_ARR = 255;  // 8-bit Auto-Reload period (0 to 255)

    // 4. Configure PWM Mode 1 on Channel 3 (OC3M = '110')
    TIM3_CCMR1 |= (6UL << 12);
    TIM3_CCER  |= (1UL << 8);  // Enable Channel 3 output (CC3E)

    // 5. Enable Timer counter
    TIM3_CR1 |= (1U << 0);
}

/**
 * @brief Trigger an ADC conversion and return 10-bit digitized value
 */
uint16_t adc_read(void) {
    ADC1_CR |= (1U << 2); // Start conversion (ADSTART)
    while (!(ADC1_ISR & (1U << 2))); // Wait for End of Conversion (EOC)
    return (uint16_t)ADC1_DR;        // Return 10-bit result (0 to 1023)
}

int main(void) {
    adc_init();
    pwm_timer_init();

    while (1) {
        // Step 1: Read 10-bit analog voltage from potentiometer (0 - 1023)
        uint16_t knob_reading = adc_read();

        // Step 2 & 3: Map 10-bit ADC to 8-bit PWM compare value
        // High-speed bitwise right-shift by 2: (1023 >> 2) = 255
        uint8_t led_brightness = (uint8_t)(knob_reading >> 2);

        // Update PWM duty cycle directly in Capture/Compare Register
        TIM3_CCR3 = led_brightness;

        // Software delay between readings
        for (volatile uint32_t delay = 0; delay < 120000; delay++);
    }

    return 0;
}

🔍 How Mini-Project 1 (Dimmer) Applies Week 4 Concepts

This project binds together two core analog-digital interfaces taught in Week 4:

1. Hardware & Circuit-Level Concept Mapping

Circuit Component Week 4 Theoretical Concept Technical Function in System
Potentiometer on A0 (PA0) Variable Voltage Divider (\(V_{\text{in}}\)) Acts as an adjustable voltage divider: \(V_{\text{out}} = V_{\text{DD}} \cdot \frac{R_2}{R_1 + R_2}\). By rotating the wiper, the user smoothly varies the input potential continuously between \(0\text{V}\) and \(+3.3\text{V}\).
STM32 ADC1 Peripheral Successive Approximation ADC (SAR) Samples the continuous analog voltage on Channel 0, holds it on an internal capacitor, and performs a binary search to quantize the voltage into a 10-bit digital representation (\(0\) to \(1023\)).
LED on D3 (PB0) Modulated Actuator & Human Eye Integration The human eye cannot perceive flicker above ~60–100 Hz. By pulsing the LED at 1 kHz, the eye’s photoreceptors integrate the pulses into an apparent, smooth brightness directly proportional to the duty cycle.
220Ω Resistor Safe Operating Area (SOA) Current Limit Ensures that peak forward current through the LED does not exceed 15 mA during the HIGH phase of the PWM waveform.

2. Firmware Code-to-Concept Breakdown

Code Statement (Framework / Bare-Metal) Week 4 Theoretical Concept Deep-Dive Explanation
analogRead(knobPin);
adc_read();		 10-Bit ADC Sampling & Quantization The ADC divides the \(3.3\text{V}\) reference range into \(2^{10} = 1024\) discrete voltage steps. Quantization step: \(Q = \frac{3.3\text{V}}{1024} \approx 3.22\text{ mV}\). A reading of \(512\) represents \(\approx 1.65\text{V}\).
int ledBrightness = map(knobReading, 0, 1023, 0, 255);
knob_reading >> 2;		 Resolution Domain Translation (10-bit to 8-bit) Translates from the ADC input domain (\(0..1023\)) to the PWM timer counter domain (\(0..255\)). In bare-metal C, bitwise right-shift by 2 (>> 2) achieves exact integer division by 4 in a single CPU clock cycle without needing slow software floating-point division.
analogWrite(ledPin, ledBrightness);
TIM3_CCR3 = led_brightness;		 Pulse Width Modulation (PWM) Duty Cycle The hardware timer counter (CNT) continuously counts up to the Auto-Reload value (ARR = 255). Whenever CNT < CCR3, the output pin is HIGH; when CNT >= CCR3, it drops LOW. Changing CCR3 modulates the Duty Cycle: \(D = \frac{\text{CCR3}}{\text{ARR}} \times 100\%\).
TIM3_CCMR1 \|= (6UL << 12); Timer Output Compare Mode 1 Selects hardware PWM Mode 1 (110 in bitfield OC3M), commanding timer hardware to automatically toggle the physical pin without CPU intervention.

6. Mini-Project 2: The Non-Blocking Metronome (Timers & ADC) ⏱️🎵

🎯 Objective

Use a timer concept to trigger an event at a highly precise interval without stopping or blocking the CPU. You will build a visual metronome where an analog input instantly controls the blinking speed of an LED, demonstrating why blocking calls like delay() are detrimental to real-time responsiveness and power management.

🛠️ Hardware & Pin Selection

  • Tempo Dial: 1x Potentiometer on A0 (variable analog tempo control).
  • Visual Tick: 1x LED with 220Ω protective resistor on D3 (connected to PB0).
  • Power & Ground: Potentiometer VCC to 5V/3V3, GND to GND. LED cathode to GND.

🧠 Step-by-Step Firmware Architecture

  1. Sample Sensor Data: Read the analog tempo dial smoothly without stopping processor execution.
  2. Map to Time Interval: Convert the raw 10-bit ADC reading (0–1023) into an elapsed millisecond window:
    • Lowest dial position: 100 ms (Fast tempo / Allegro)
    • Highest dial position: 2000 ms (Slow tempo / Largo)
  3. The Non-Blocking Timer Logic:
    • If firmware executes delay(interval), the CPU completely halts. It cannot sample the knob until the delay finishes, making the dial feel laggy and unresponsive.
    • Solution: Use background hardware timing (millis() or ARM Cortex-M SysTick timer). Store the previousMillis timestamp and continuously compare against currentMillis.
  4. Execute & Update: When (currentMillis - previousMillis) >= interval, invert the LED state and reset the milestone.
  5. Verify Multitasking: When rotating the knob, the blink rate adjusts immediately with zero lag, proving the system is non-blocking.

// ============================================================================
// Mini-Project 2: The Non-Blocking Metronome (High-Level Framework)
// ============================================================================

// Hardware Pins
#define tempoKnobPin A0
#define metronomeLedPin 3

// Timer tracking variables
unsigned long previousMillis = 0; 
int ledState = LOW;

void setup() {
  Serial.begin(115200);
  
  pinMode(tempoKnobPin, INPUT);
  pinMode(metronomeLedPin, OUTPUT);
  
  // Set ADC to 10-bit mode (0-1023 range)
  analogReadResolution(10); 
  
  Serial.println("--- Non-Blocking Metronome Started ---");
}

void loop() {
  // Step 1: Sample Sensor Data smoothly
  int rawTempo = analogRead(tempoKnobPin);
  
  // Step 2: Map raw ADC (0-1023) to millisecond interval (100ms to 2000ms)
  int interval = map(rawTempo, 0, 1023, 100, 2000);
  
  // Step 3: The Non-Blocking Timer Logic
  unsigned long currentMillis = millis();
  
  if (currentMillis - previousMillis >= interval) {
    // Save the last time we blinked the LED
    previousMillis = currentMillis;
    
    // Step 4: Toggle LED state
    if (ledState == LOW) {
      ledState = HIGH;
    } else {
      ledState = LOW;
    }
    digitalWrite(metronomeLedPin, ledState);
    
    // Step 5: Verify Multitasking (prints without lagging the loop)
    Serial.print("Tick! Current Tempo: ");
    Serial.print(interval);
    Serial.println(" ms");
  }
}

// Mini-Project 2: The Non-Blocking Metronome (Bare-Metal Embedded C)
// Hardware: STM32 Nucleo-C031C6
// Architecture: ARM Cortex-M SysTick 1ms Timer + ADC1 (PA0) + GPIO (PB0)
// ============================================================================

#include <stdint.h>

// 1. STM32 Base Addresses & Memory-Mapped Registers
#define RCC_BASE            (0x40021000UL)
#define RCC_IOPENR_REG      (*(volatile uint32_t *)(RCC_BASE + 0x34UL))
#define RCC_APBENR2_REG     (*(volatile uint32_t *)(RCC_BASE + 0x40UL))

#define GPIOA_BASE          (0x50000000UL)
#define GPIOA_MODER_REG     (*(volatile uint32_t *)(GPIOA_BASE + 0x00UL))

#define GPIOB_BASE          (0x50000400UL)
#define GPIOB_MODER_REG     (*(volatile uint32_t *)(GPIOB_BASE + 0x00UL))
#define GPIOB_BSRR_REG      (*(volatile uint32_t *)(GPIOB_BASE + 0x18UL))

// ARM Cortex-M Core SysTick Timer Registers (0xE000E010)
#define SYST_CSR            (*(volatile uint32_t *)(0xE000E010UL)) // Control & Status
#define SYST_RVR            (*(volatile uint32_t *)(0xE000E014UL)) // Reload Value
#define SYST_CVR            (*(volatile uint32_t *)(0xE000E018UL)) // Current Value

// ADC1 Registers (PA0 / Analog Channel 0)
#define ADC1_BASE           (0x40012400UL)
#define ADC1_ISR_REG        (*(volatile uint32_t *)(ADC1_BASE + 0x00UL))
#define ADC1_CR_REG         (*(volatile uint32_t *)(ADC1_BASE + 0x08UL))
#define ADC1_CFGR1_REG      (*(volatile uint32_t *)(ADC1_BASE + 0x0CUL))
#define ADC1_CHSELR_REG     (*(volatile uint32_t *)(ADC1_BASE + 0x28UL))
#define ADC1_DR_REG         (*(volatile uint32_t *)(ADC1_BASE + 0x40UL))

// Hardware Pin Definitions matching Wokwi circuit:
// Tempo Dial Potentiometer = PA0 (A0)
// Metronome LED = PB0 (D3)
#define METRONOME_LED_PIN   (0U) // PB0

// Global millisecond timestamp incremented by SysTick ISR
volatile uint32_t ms_ticks = 0;

/**
 * @brief ARM Cortex-M SysTick Exception Handler (Fires every 1ms)
 */
void SysTick_Handler(void) {
    ms_ticks++;
}

/**
 * @brief Initialize 1 ms SysTick Hardware Timer
 * CPU Clock = 48 MHz -> 48,000 clock cycles = 1 ms
 */
void systick_init(void) {
    SYST_RVR = 48000UL - 1UL; // Set reload value for 1ms tick
    SYST_CVR = 0;             // Clear current counter
    SYST_CSR = (1U << 2) |    // Bit 2: Core processor clock source
               (1U << 1) |    // Bit 1: Enable SysTick exception interrupt
               (1U << 0);     // Bit 0: Enable counter
}

uint32_t get_millis(void) {
    return ms_ticks;
}

void metronome_hardware_init(void) {
    // 1. Enable GPIOA, GPIOB, and ADC1 peripheral clocks
    RCC_IOPENR_REG  |= (1U << 0);  // GPIOA clock enable (PA0)
    RCC_IOPENR_REG  |= (1U << 1);  // GPIOB clock enable (PB0)
    RCC_APBENR2_REG |= (1U << 20); // ADC clock enable

    // 2. Configure PB0 (D3) as Output ('01' in MODER) for Metronome LED
    GPIOB_MODER_REG &= ~(3UL << (METRONOME_LED_PIN * 2));
    GPIOB_MODER_REG |=  (1UL << (METRONOME_LED_PIN * 2));

    // 3. Configure PA0 (A0) as Analog ('11' in MODER) for Tempo Dial
    GPIOA_MODER_REG |=  (3UL << (0 * 2));

    // 4. ADC Calibration & Enable
    ADC1_CR_REG |= (1U << 31); // Start calibration (ADCAL)
    while (ADC1_CR_REG & (1U << 31));

    ADC1_ISR_REG |= (1U << 0); // Clear ADRDY
    ADC1_CR_REG  |= (1U << 0); // Assert ADEN
    while (!(ADC1_ISR_REG & (1U << 0)));

    // 5. Configure 10-bit resolution & Channel 0 selection
    ADC1_CFGR1_REG &= ~(3UL << 3);
    ADC1_CFGR1_REG |=  (1UL << 3); // 10-bit mode (0 to 1023)
    ADC1_CHSELR_REG =  (1UL << 0); // Channel 0
}

uint16_t read_tempo_dial(void) {
    ADC1_CR_REG |= (1U << 2); // Start ADC conversion (ADSTART)
    while (!(ADC1_ISR_REG & (1U << 2))); // Wait for EOC
    return (uint16_t)ADC1_DR_REG;        // Return 10-bit reading (0 to 1023)
}

int main(void) {
    metronome_hardware_init();
    systick_init();

    uint32_t previous_millis = 0;
    uint8_t  led_state       = 0;

    while (1) {
        // Step 1: Read analog tempo dial smoothly without stopping the CPU
        uint16_t raw_tempo = read_tempo_dial();

        // Step 2: Map 10-bit ADC (0..1023) to interval: 100ms to 2000ms
        // Formula: interval = 100 + (raw_tempo * (2000 - 100)) / 1023
        uint32_t interval = 100UL + ((uint32_t)raw_tempo * 1900UL) / 1023UL;

        // Step 3: Non-blocking elapsed time comparison
        uint32_t current_millis = get_millis();
        if ((current_millis - previous_millis) >= interval) {
            previous_millis = current_millis; // Update last blink time

            // Step 4: Toggle LED state atomically via BSRR register on PB0
            led_state = !led_state;
            if (led_state) {
                // Set PB0 HIGH (Write to lower 16 bits of BSRR)
                GPIOB_BSRR_REG = (1UL << METRONOME_LED_PIN);
            } else {
                // Reset PB0 LOW (Write to upper 16 bits of BSRR)
                GPIOB_BSRR_REG = (1UL << (METRONOME_LED_PIN + 16U));
            }
        }

        // The CPU remains completely free to execute background tasks!
    }

    return 0;
}

7. Real-World Embedded Systems Examples

Timers, ADCs, and PWM are the trifecta of modern embedded control. Study these three industry-standard applications:

Example 4.1: Automotive Ambient Light Automatic Headlight Dimmer 🚗💡

  • The Real-World Scenario: Luxury vehicles feature automatic headlamps that continuously sense external ambient light levels. When driving into an underpass, tunnel, or during twilight, the headlights automatically illuminate and smoothly scale their brightness.

  • Key Concept Connection:

    • An ambient light photodiode produces a voltage proportional to lux, sampled by a 12-bit ADC.
    • The microcontroller maps this reading to an inverse 1 kHz PWM duty cycle driving high-power LED driver MOSFETs. Smooth duty cycle increments prevent abrupt illumination steps that could distract the driver.

  • Firmware Architectural Pattern:

    #include <stdint.h>

void update_headlight_illumination(void) {
    // 1. Sample ambient brightness (0 = Pitch Black, 4095 = Bright Sunlight)
    uint16_t ambient_lux = read_adc_channel(ADC_CHANNEL_LIGHT_SENSOR);

    // 2. Inverse mapping: Darker ambient requires brighter headlights
    uint16_t target_pwm_duty = 4095 - ambient_lux;

    // 3. Update Hardware Timer Compare Register (CCR) controlling LED drivers
    TIM1->CCR1 = target_pwm_duty; 
}

Example 4.2: Hospital ICU Vital Signs Heartbeat Metronome ❤️🔊

  • The Real-World Scenario: In an intensive care unit (ICU) bedside patient monitor, an audio beep and flashing heart icon synchronize with the patient’s electrocardiogram (ECG) heart rate (e.g., 60 to 180 beats per minute).

  • The Non-Blocking Requirement:

    • If the firmware used delay() to time the beeps, the processor would be completely paralyzed and unable to process urgent incoming arrhythmia alarms or nurse touch-screen inputs!
    • Using a non-blocking SysTick timer state machine, the monitor tracks beep duration and heartbeat intervals cooperatively.

  • Firmware Architectural Pattern:

    uint32_t last_heartbeat_timestamp = 0;
uint32_t beat_interval_ms = 857; // 70 Beats Per Minute (60,000 / 70)

void process_vital_signs(void) {
    uint32_t now = get_systick_millis();

    // Non-blocking timer check
    if (now - last_heartbeat_timestamp >= beat_interval_ms) {
        last_heartbeat_timestamp = now;

        TRIGGER_HEARTBEAT_AUDIO_BEEP();
        FLASH_CARDIAC_LED_ON_DISPLAY();
    }

    // CPU remains 100% available to evaluate emergency alarms and touch inputs
    check_blood_oxygen_saturation();
    service_touchscreen_events();
}

Example 4.3: Drone Brushless Motor Electronic Speed Controller (ESC) 🚁

  • The Real-World Scenario: A quadcopter flight controller must dynamically adjust the rotational speeds of 4 high-RPM brushless motors hundreds of times per second to remain stable in turbulent winds.

  • Hardware Timer PWM Generation:

    • The flight computer runs a hardware timer generating standard servo PWM pulses at 400 Hz (period \(T = 2.5\text{ ms}\)).
    • Pulse widths between 1000 \(\mu\text{s}\) (0% throttle) and 2000 \(\mu\text{s}\) (100% throttle) command the Electronic Speed Controllers with sub-microsecond precision.

  • Firmware Architectural Pattern:

    #define THROTTLE_MIN_PULSE_US   (1000U)
#define THROTTLE_MAX_PULSE_US   (2000U)

void set_motor_thrust(uint8_t motor_id, float throttle_percentage) {
    // Calculate pulse width in microseconds (1000 to 2000 us)
    uint32_t pulse_us = THROTTLE_MIN_PULSE_US + 
                        (uint32_t)(throttle_percentage * 10.0f);

    // Update Timer Capture/Compare Register directly
    switch(motor_id) {
        case 0: TIM2->CCR1 = pulse_us; break; // Motor Front-Left
        case 1: TIM2->CCR2 = pulse_us; break; // Motor Front-Right
        case 2: TIM2->CCR3 = pulse_us; break; // Motor Rear-Left
        case 3: TIM2->CCR4 = pulse_us; break; // Motor Rear-Right
    }
}

8. Important Exam Practice Questions

Question 1: Timer Overflow Frequency Calculation

NoteClick to View Question & Options

A microcontroller timer is clocked by an internal clock source of 16 MHz. The Prescaler (PSC) is set to 15, and the Auto-Reload Register (ARR) is set to 999. What is the resulting timer overflow frequency?

Options:
- A) 100 Hz
- B) 500 Hz
- C) 1,000 Hz (1 kHz)
- D) 10,000 Hz

Tip✅ Correct Answer: C

Explanation:
\[f_{\text{timer}} = \frac{f_{\text{CLK}}}{(\text{PSC} + 1) \times (\text{ARR} + 1)} = \frac{16,000,000}{(15 + 1) \times (999 + 1)} = \frac{16,000,000}{16 \times 1000} = \mathbf{1,000\text{ Hz}}\ (1\text{ kHz})\]

Question 2: ADC Quantization Resolution

NoteClick to View Question & Options

A 10-bit Analog-to-Digital Converter (ADC) can digitize an incoming analog signal into how many distinct discrete voltage levels?

Options:
- A) 10 levels
- B) 256 levels
- C) 1024 levels
- D) 4096 levels

Tip✅ Correct Answer: C

Explanation:
An \(N\)-bit ADC resolves an input into \(2^N\) discrete numerical steps. For a 10-bit converter: \(2^{10} = \mathbf{1024}\) distinct levels (ranging from 0 to 1023).

Question 3: Combinational vs. Sequential Digital Elements

NoteClick to View Question & Options

Which of the following is the fundamental distinguishing characteristic of a sequential digital logic element compared to a combinational element?

Options:
- A) Sequential circuits do not require electric power to operate
- B) Sequential circuits contain memory (storage) elements such as flip-flops, so the output depends on both current inputs and previous state history
- C) Combinational circuits require a continuous clock pulse signal
- D) Sequential circuits can only process analog signals

Tip✅ Correct Answer: B

Explanation:
Combinational circuits (like adders and multiplexers) produce outputs based strictly on current inputs. Sequential circuits (like registers, counters, and timers) incorporate memory elements (flip-flops) and update their state based on clock transitions.

Question 4: Microcontroller Low-Power Modes

NoteClick to View Question & Options

In battery-powered embedded systems, which microcontroller operating mode retains SRAM contents while turning off the high-speed CPU clock until an external interrupt occurs?

Options:
- A) Shutdown Mode
- B) Sleep / Stop Mode
- C) Factory Reset Mode
- D) Thermal Protection Mode

Tip✅ Correct Answer: B

Explanation:
Sleep and Stop modes gate the high-frequency clock to the CPU core while keeping SRAM powered, allowing instantaneous wakeup when an external pin change or timer interrupt triggers.
